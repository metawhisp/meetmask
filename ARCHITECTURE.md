## 1. Что это (одним абзацем)
MEETAMASK — macOS-приложение + маркетплейс масок. Пользователь надевает кастомные маски (AR-эффекты на лицо/руки) на свою камеру в Meet, Zoom, FaceTime и любом видео-приложении. Маска = самодостаточная HTML-страница. Создатели публикуют маски на сайте-маркетплейсе; пользователи их ставят и используют. Идейно — преемник Snap Camera. Платформа на старте — **только macOS**.

## 2. Три «лица» продукта + что под капотом

### Что видит пользователь (surfaces)
| # | Поверхность | Роль | Кто пользуется |
|---|---|---|---|
| A | **Приложение MEETAMASK** (нативный SwiftUI, Liquid Glass) | Лицо продукта: галерея масок, выбрать/включить маску, живое превью, онбординг, настройки | Конечный пользователь |
| B | **Маркетплейс (сайт + БД)** | Публикация и поиск масок; «Добавить в MEETAMASK» | Создатели (публикуют) + пользователи (берут) |
| C | **Бэкенд (API, аккаунты, хранилище, модерация)** | Аккаунты, хранение масок, модерация, раздача | Обслуживает A и B |

### Что НЕ видит пользователь (внутренние компоненты, «под капотом»)
| Компонент | Роль |
|---|---|
| **Виртуальная камера** (CMIO system extension) | Регистрирует «MEETAMASK Camera», которую видят все видео-приложения. Принимает кадры → отдаёт в Meet/Zoom. |
| **Render-движок** (CEF / Chromium offscreen) | Невидимый «мотор»: рендерит HTML-маску офскрин (с MediaPipe + камерой) → кадры. Не имеет окна → не зависает при скрытии приложения. **Запускается и управляется приложением**, пользователь его не видит. |

**Метафора:** приложение — это машина (лицо), движок — двигатель под капотом, виртуальная камера — выхлоп, который видит Meet. Пользователь водит машину, а не дёргает двигатель.

## 3. User flows (как это работает для людей)

### 3.1 Использовать маску (конечный пользователь)
1. Открыл **приложение MEETAMASK**.
2. В галерее выбрал маску, нажал **«Включить»**.
3. *(под капотом)* приложение запускает движок с этой маской; движок берёт реальную вебку, прогоняет через маску (MediaPipe-трекинг + эффекты), отдаёт кадры в MEETAMASK Camera.
4. В Meet/Zoom выбрал камеру **«MEETAMASK Camera»** — он в маске.
5. Свернул/спрятал приложение — **маска продолжает идти** (движок без окна).

**Критерий приёмки:** маска видна в Meet в реальном времени, ~30fps, и не зависает при скрытии приложения.

### 3.2 Опубликовать маску (создатель)
1. Сделал самодостаточную HTML-маску (по контракту, см. §5; пример — `ar-dr-strange`).
2. Зашёл на **сайт-маркетплейс**, залил маску (zip/папка с `index.html` + превью).
3. Маска проходит **модерацию** (безопасность чужого кода — критично).
4. После одобрения — появляется в галерее маркетплейса и доступна всем.

### 3.3 Поставить маску из маркетплейса (пользователь)
1. На сайте нашёл маску → **«Добавить в MEETAMASK»**.
2. Браузер открывает deep link `meetamask://install?id=...`.
3. Приложение скачивает маску в локальную библиотеку → она появляется в галерее.

## 4. Поток кадров (техническая сердцевина)
```
Реальная вебка
   ↓ getUserMedia (внутри движка)
HTML-маска в CEF (MediaPipe трекинг + отрисовка эффектов на canvas)
   ↓ CEF OnPaint / OnAcceleratedPaint (офскрин-кадр, BGRA / IOSurface)
Render-движок → передаёт кадр
   ↓ CMIO sink (буфер-очередь)
Виртуальная камера (extension): relay sink → source
   ↓
«MEETAMASK Camera» (source stream)
   ↓
Google Meet / Zoom / FaceTime
```
Ключ: движок берёт **реальную** камеру на входе и отдаёт **виртуальную** на выходе — петли нет.

## 5. Контракт маски (что такое «маска» технически)
- Маска = **папка с самодостаточным `index.html`**, который запускается **как есть** (Model A). Плюс манифест: имя, превью, автор, версия.
- Трекинг — забота маски (MediaPipe Hands/Face/Pose/none) — рантайм не навязывает модель.
- Захватывается **вся отрендеренная страница** (видео + canvas'ы + CSS), не один canvas.
- Безопасность (чужой UGC-код): изоляция **внутри Chromium** — отдельный профиль, строгий CSP, **сетевой allow-list** (MediaPipe локально / перехват CDN), без доступа к ФС.
- Автостарт (без ручного «Enter Experience»), своё UI маски прячется из кадра, аудио в v1 — дропается (только видео).
