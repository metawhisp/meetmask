# MEETAMASK — Спецификация

## Контекст
MEETAMASK — macOS-приложение: пользователь надевает кастомные маски (AR-эффекты) на свою камеру в Google Meet и любом другом приложении с камерой. Маски — самодостаточные HTML-страницы; есть сайт-маркетплейс, где их публикуют. Полный контекст и зафиксированные решения — в памяти проекта (`project_meetomask.md`).

## Архитектурное решение (зафиксировано)
Приложение регистрирует себя как **виртуальную камеру** через **Camera Extension (CMIOExtension)** — современный путь macOS 12.3+ (подача кадров из app — 13+).
Почему именно так (по критерию «качество + удобство пользователя»):
- работает во **всех** приложениях (Meet, Zoom, FaceTime, Teams, Discord) — юзер учится один раз;
- долговечно (путь Snap Camera / OBS / Camo);
- чужой UGC-HTML крутится в **нашем** офскрин-Chromium, а не внутри страницы Meet → безопасно и стабильно.

Отвергнуто: Chrome-расширение с перехватом `getUserMedia` — только Meet+Chrome, ломается от обновлений Google, небезопасно для чужих масок.

## Дизайн и UI (зафиксировано)
- Приложение — **нативное SwiftUI** под SDK macOS 26, чтобы получить **настоящий Apple Liquid Glass** (родной язык дизайна macOS 26 Tahoe), а не CSS-имитацию. Тон: серьёзный, профессиональный.
- Ключевые элементы: **галерея пресетов** + много **интерактивного взаимодействия** (интерактивное стекло, плавные морфинги/переходы, живое превью результата).
- **Граница ответственности:** SwiftUI = весь UI (галерея, контролы, онбординг, превью). **CEF/Chromium — НЕ UI**, а headless-рендерер масок за кадром (HTML-страница → кадры → виртуальная камера). Стеклянный фронт + безголовый рендерер сзади.
- Точные имена glass-API подтверждаются по установленному SDK перед UI-кодом (без выдумок).

## M1 — Ядро-камеры (детально)

### Цель
Нативная виртуальная камера на macOS, которую кормит наш хост-процесс и которую Google Meet (Chrome) видит и показывает. Снимает риск #1 (узнаёт ли Meet нашу камеру) и даёт фундамент для масок.

### Не-цели (вне scope M1)
- Никакого CEF, MediaPipe, ar-dr-strange, масок. Только тест-паттерн / реальная камера-passthrough.
- Никакого сайта, БД, аккаунтов.
- Минимальный UI — только нативное SwiftUI-окно для активации расширения (фундамент под Liquid Glass, но без галереи; галерея — M4).
- Нотаризация / раздача — потом (для локальной разработки хватает developer mode).

### User stories
- **US-1 (риск-килл).** Как разработчик MEETAMASK, я хочу, чтобы наша виртуальная камера появлялась и показывала кадры в Google Meet (Chrome) на macOS, чтобы подтвердить выполнимость продукта до вложений в маски и сайт.
  - Приёмка: на `meet.google.com` в Chrome в списке камер есть «MEETAMASK Camera» и показывает наш тест-паттерн (не чёрный экран).
- **US-2 (свои кадры).** Как хост-приложение, я хочу отдавать произвольные кадры в виртуальную камеру из своего процесса, чтобы туда потом шли отрендеренные маски.
  - Приёмка: кадры, сгенерированные приложением (отличимые от внутреннего паттерна расширения), видны в Meet; стабильно 1280×720@30 без видимых лагов.
- **US-3 (реальная камера).** Как пользователь, я хочу видеть свою реальную камеру через «MEETAMASK Camera», чтобы база работала в реальном времени до наложения маски.
  - Приёмка: приложение захватывает вебку и гонит её через виртуальную камеру; в Meet видно реальное видео в реальном времени (субъективно без задержки) при 30fps.

### Технический подход (на базе проверенных реализаций, без выдумок)
- Два таргета Xcode: **host-app** + встроенный **Camera Extension** (шаблон «Camera Extension»). Оба под одним Team ID (по умолчанию org `UT6WGPGTGR`).
- За основу — официальный сэмпл Apple «Creating a Camera Extension with Core Media I/O» (рабочий CMIOExtension с тест-паттерном). Адаптируем bundle ID / имена / Team ID. Точную API-поверхность (`CMIOExtensionProvider/Device/StreamSource`, `OSSystemExtensionRequest`) берём из сэмпла — не изобретаем.
- Подача кадров из app (US-2/3): **sink-стрим** + **CMSimpleQueue**; app — продюсер, расширение — релей sink→source. Референс — OBS `mac-virtualcam`. Причина именно так (а не XPC/App Groups): расширение работает как root, app — как user.
- Локальная разработка: `systemextensionsctl developer on`; активация из app через `OSSystemExtensionRequest`; подтверждение в System Settings (один раз). SIP не трогаем — проверим на первой установке.

### Итерации и чек-листы

**Итерация 1 — камера с тест-паттерном видна в Meet (риск #1)**
- [ ] Xcode-проект: host-app + Camera Extension, оба под Team ID `UT6WGPGTGR`.
- [ ] Адаптировать сэмпл Apple: расширение само генерит тест-паттерн (бегущие полосы / счётчик), 1280×720@30.
- [ ] `systemextensionsctl developer on`; активация расширения из app; подтвердить в System Settings.
- [ ] Проверка: `systemextensionsctl list` — расширение enabled.
- [ ] Санити: «MEETAMASK Camera» в Photo Booth / QuickTime.
- [ ] getUserMedia тест-страница в Chrome (держим в репо) — камера видна, паттерн идёт.
- [ ] **ГЛАВНОЕ:** камера видна и стримит на `meet.google.com` (Chrome).
- [ ] Бонус: Zoom, FaceTime.
- [ ] Записать результат в `PROGRESS.md` (зелёно/красно + детали).

**Итерация 2 — приложение кормит камеру своими кадрами**
- [ ] Добавить sink-стрим в расширение; релей sink→source.
- [ ] В app: enqueue `CMSampleBuffer` в sink через `CMSimpleQueue` (по образцу OBS).
- [ ] App генерит отличимый кадр (счётчик / время) — проверить, что в Meet именно он, а не внутренний паттерн.
- [ ] Стабильность 1280×720@30 без дропов/лага (визуально + лог fps).
- [ ] (TDD) юнит-тесты на enqueue/dequeue-обёртку и конвертацию формата — red→green.
- [ ] `PROGRESS.md`.

**Итерация 3 — реальная камера через нашу виртуальную (real-time)**
- [ ] `AVCaptureSession`: захват вебки в app.
- [ ] Конвертация кадра в формат стрима; подача в sink.
- [ ] В Meet видно реальное видео в реальном времени @30fps, латентность субъективно низкая.
- [ ] Замерить fps и латентность, записать числа.
- [ ] `PROGRESS.md`. → после этого M1 закрыт, переходим к M2 (маски).

### Подход к тестам (честно про TDD)
- Юнит-тестим (TDD, сначала падающий тест): генератор тест-паттерна, конвертация пиксельных форматов, обёртка `CMSimpleQueue` (enqueue/dequeue), тайминг/fps-математика.
- НЕ юнит-тестим (нельзя автоматизировать): «камера видна в Meet» — это ручная/интеграционная проверка по чек-листу + getUserMedia тест-страница в репо. Тут «тест» = воспроизводимый чек-лист и визуальное подтверждение, а не unit.

### Риски
- **R1 (топ):** Chrome/Meet не показывает виртуалку (классификация как Screen Recording / System Extension). → front-load в Итерации 1; если красно — копаем entitlements / Chrome-флаги / разрешения до того, как строить дальше.
- R2: рассинхрон формата / латентность хендофа app→extension. → строго по образцу OBS.
- R3: не вытягиваем 30fps HD. → замеряем в Итерации 3.
- R4: трение подписи / активации в dev. → developer mode; сертификаты есть.
